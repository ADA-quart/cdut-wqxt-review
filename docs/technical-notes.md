## 架构与原理

### 为什么必须用真实浏览器

问渠学堂有动态防护（瑞数），纯 HTTP 请求会被拒；本工具用本机已安装的 Edge/Chrome 真实内核完成登录与接口初始化，窗口默认藏在屏幕外。

### 数据流

```
登录 ─→ 课程/课次 ─→ 下载图片 ─→ 清洗(去重) ─→ 转 MD(OCR) ─→ 校订(纠错+公式)
                                                              │
                                      ┌───────────────────────┘
                                      ▼
                          生成深度笔记(note.md + note.pdf)
                                      │
                    ┌─────────────────┼──────────────────┐
                    ▼                 ▼                  ▼
                复习台(标记/卡片/AI)  审计(质量核对)   导出 zip(手机/Obsidian)
```

### 退出登录（2026-10 实测）

- 站点的 `/logout` **只是前端路由**：返回 200 + 应用 HTML，不清任何会话（访问后 `infosimple` 仍返回账号）。
- 官方登出流程（从 app bundle 读出）：清 `_token` / `live_token` / `iPlanetDirectoryPro`，再跳
  `window.CONFIG.CASAPI + /index.php?r=auth/cmc-loginout&tenant_code=<租户>&forward=<完整 URL>`。
  本站实测 `CASAPI=https://yjapi.wqxt.cdut.edu.cn/casapi`、`tenant_code=21`——都从页面 `CONFIG` 读，不要写死。
- 本项目登出实现（`wqxt.mjs` 的 `logout()`）：统一认证登出 → 清 cdut 域下的鉴权 cookie
  （`JWTUser` / `_token` / `live_token` / `iPlanetDirectoryPro` / `SESSION` / `PHPSESSID`，**保留**瑞数 WAF cookie）→
  回站点复检；未清干净时返回 `ok:false`，不假装成功。
- 附带约束：登出后页面停在统一认证页，`browser.mjs` 的「工作页面」判定必须把 CAS 主机也算合法，
  否则每次状态查询都会新开一个标签页。

### 任务模型与省 token 设计

- 三类任务统一走 SSE 推送：下载 / 转 MD / LLM；**同目标同操作幂等**（重复提交直接复用进行中的任务）。
- 生成笔记三遍加工 + 整理稿缓存：原文没变重跑只花「成稿 + 必记」的钱。
- DeepSeek 推理模型自动管理思考预算；批量环节（整理 / 必记 / 判定）关闭思考，实测 40 页课次输出 tokens 从 5 万降到 1.4 万、耗时 300s → 90s、页覆盖 15/40 → 40/40。

### 笔记的两条链路（2026-10-09 实测）

`llm.notePipeline` 决定走哪条：`auto`（默认）/ `vision` / `text`。
视觉档位按「视觉档 → 本机 Ollama → 多模态文本档」自动探测（探不通的档位缓存在进程内，下次直接跳过），
一个都没有才回落文本链路。

| | 视觉链路（默认） | 文本链路（回落） |
| --- | --- | --- |
| 输入 | 每页**幻灯片截图** + 该页讲稿切片 | 整份 OCR 原文 + 该页讲稿切片 |
| 工序 | 逐页整理 → 重组 → 提炼顶部块 | 整理稿 → 成稿 → 提炼顶部块 |

**同课次完整口径**（2026-10-09，含自动审计与知识点补全，同一份代码、课前清空整理稿缓存）：

| | 视觉链路 | 文本链路 | 差 |
| --- | --- | --- | --- |
| 生成笔记 | 28.8k 入 / 13.7k 出 · 63 秒 | 57.1k 入 / 24.3k 出 · 134 秒 | 入 −50%、出 −44%、时间 −53% |
| 审计 + 知识点补全 | 51.5k 入 / 9.1k 出 · 56 秒 | 63.7k 入 / 16.7k 出 · 81 秒 | 入 −19%、出 −45%、时间 −31% |
| **合计** | **80.2k 入 / 22.8k 出 · 119 秒** | **120.8k 入 / 41.0k 出 · 215 秒** | **入 −34%、出 −44%、时间 −45%** |
| 审计「不支持」条目 | 2 | 2 | 持平 |
| 知识点覆盖（同一份 57 条清单，含补全） | 57/57 | 57/57 | 持平 |

中间产物必须分开存：视觉链路写 `.note.work.vision.md`，文本链路写 `.note.work.md`。
两者格式不同，共用文件名会让「切链路」时误用对方的缓存（实测文本链路因此跑出 96 秒的假成绩）。

**为什么必须两段式**：试过「一遍过直接写完整笔记」——模型会**记错页码**（把第 7/8 页的矩阵式标成第 6 页、
把胡克定律标成第 7 页），角标跳不到正确页，审计随即判「无依据」12 条。改成「先逐页整理（页码绑在每页上）、
再重组（纯文本，角标原样搬运）」后降到 2 条。

**视觉链路的确定性护栏**（不靠模型自觉）：

- 角标规整：`⁽²⁾` 这类上标引用还原成 `[[课次.pdf#page=N|N]]`，保证可点击、可审计；
- 覆盖自检 + 按页补漏：哪页一条都没引用，就拿那页的图再补一次；
- 图兜底：模型没贴图时，自动附上该课次**面积最大的几张关键图**（校徽/涂鸦已被尺寸过滤挡掉）；
- 无效图剔除：指向不存在文件的图片引用一律去掉；
- 术语：提示词要求「以幻灯片为准」（听错的词按幻灯片写法纠正），语义层面的核对交给生成后的质量审计。

  试过两条更"自动"的路，都不成立，记在这里免得重走：
  ① 从 OCR 文本抽术语表——中文没空格，纯词频/短行法抽出来是「面上的应力边界条」这类垃圾；
  ② 用字符相似度给条目回找正确页码——「第 2 行 j=1…」会被匹配到第 4 页，噪声太大。
  另外注意：**md 里的文字就是幻灯片上的文字**，模型看图时已经看到正确写法，再塞一份从 md 抽的词表是重复劳动。

**知识点补全**（补上了视觉链路的覆盖差距）：审计会提出一份知识点清单并逐条判定
`covered / partial / missing`；`runAudit` 在写完修正笔记之后，把 `partial + missing` 的条目
（最多 20 条）交给 LLM，用**这几页的课件原文 + 讲稿切片**补写要点（带页码角标），
追加成笔记末尾一个 `### 📌 知识点补全（自动）` 小节（已有就替换，不重复追加），
再花一次小调用核对「这些点现在算不算覆盖」，把清单状态改回 ✅——所以 `.points.md`
不会出现「清单说缺、笔记里其实有」的矛盾。

实测同一课次：`44 ✅ / 10 ⚠️ / 3 ❌` → 补写 13 条（1,174 字） → 核对 13/13 → **57/57 全覆盖**。
开关：`config.automation.supplementAfterAudit`（默认开）。

注意顺序：补全必须在「审计修正落盘」**之后**执行——否则那次整篇写入会把补写内容冲掉（踩过）。

### 验证口径：评审者与被评审者同模

2026-10-09 核对本机配置与线程记录：开发本项目的 agent 与笔记 / 图注 / 校订用的是**同一个模型**
（`deepseek-v4-flash`，经 `api.deepseek.com`；agent 走 Responses API，项目代码走 Chat Completions），
只是两条独立通道、各自计费。

因此「这样写更好」这类判断要打折：同模评审会共享盲区（偏爱的句式、不敏感的错法都一致）。
本项目对可验证的部分一律不靠自评，而是留下可复跑的机器证据：

- 文件是否存在、HTTP 状态码、任务日志里的实际行、token 用量；
- 确定性函数（如 `stripPlaceholderSections`、`narrationByPage`）用**干跑对比**验证，不靠模型保证；
- 提示词与对齐规则的取舍写成 A/B 实测记录（见「回放 / 音轨」一节的 initial_prompt 实测）。

换用不同模型（如 glm 系列）复评时，可能暴露同模评审看不到的问题——升级模型或改提示词后，
建议至少重跑一次「同一课次的笔记 + 审计」再比较。

## 已验证结果（节选）

- **下载**：单课次 120 张图 / 整课 4 课次 197 张图，0 失败；图片 1280×720 JPEG。
- **转 MD**：77 页课次全量转换 9.6 分钟（V100），48 块公式 + 53 行内公式，公式识别准确率高（正文零星 OCR 笔误，交给「校订」修）。
- **清洗**：317 帧样本中连续冗余 24%；空白过渡帧与等待页二维码自动识别。
- **深度笔记**（40 页测井课）：22 小节 + 22 条讲解 + 2 道习题折叠答案 + 112 个页码角标；**40/40 页全部被引用**；输出 ~1.6 万 tokens / 95 秒。
- **审计**：61 个知识点提取，52 覆盖 / 8 不完整 / 1 缺失；忠实度 48 通过 / 3 部分（真实抓到过 OCR 传导错误，如 K₄ → K_d、R_xo/R_t → R_xo/R_m，已自动修正）。
- **安卓端**：内容包（44 文件）导入 → 笔记 1.1 万字符 / 39 张课件图离线显示 / 对话与公式全渲染，零报错；平板模拟器（2880×1800）横竖屏实机验收；CI 自动构建 + 固定签名发布。

## 回放 / 音轨（2026-10 探测记录）

- **形态**：`content.playback.url` = `https://resource.wqxt.cdut.edu.cn/play/default/YYYY/MM/DD/<hash>_1920_1080.mp4`；
  实测 144 条回放全部同构直链 MP4、**无签名参数**（`file_list` 同址，另附一张封面 jpg）。
- **直连取不到**（2026-10-09 复测，15 条跨 3 门课全复现）：
  - 不带参数 → **500**（nginx 错误页，非瑞数挑战页）；带随机 `clientUUID` 或原样重放签名 → **403**；
  - 同域封面 `play/default/Pic/.../*.jpg` 正常 200，不存在的 jpg 正常 404，
    而不存在的 **mp4 同样 500**——说明是 mp4 这条路径的准入校验，不是文件级 404。
- **可用姿势**：播放器页（`/coursevideo?id=<课程>&sub_id=<课次>`，会跳到 `/videoroom`）自己会取流，
  真实请求形如 `.../<hash>_1920_1080.mp4?clientUUID=<uuid>&t=<用户ID>-<时间戳>-<哈希>`，
  响应 **206 video/mp4**。签名由播放器侧生成且短时有效，不复刻。
  **实现：CDP `Fetch` 在 Response 阶段拦播放器自己的响应，`takeResponseBodyAsStream` + `IO.read` 落盘**（`server/replay.mjs`）。
- **踩过的坑**：边收边把字节喂 `ffmpeg -i pipe:0`，到约 700MB 时 ffmpeg 提前退出，
  stdin 的 EPIPE 以未捕获 `error` 事件把 Node 进程打挂。现改为先落临时 mp4（可 seek），
  ffmpeg 从文件抽音轨（16kHz 单声道 AAC），抽完删视频；ffmpeg/stdin 的 error 一律接住。
- **平台自带「语音识别」不可依赖**：`/courseapi/v3/web-socket/search-trans-result?course_id&sub_id`
  能直接拿到整节课的同传文本（`BeginSec`/`EndSec`/`Text`/`TransText`），但 2026-10-09 抽样
  144 个课次只有 107 个有（74%）——当学期新录课次仅 4/28（14%），上学期 103/116（89%）。
  缺失时返回 `code=10002`。故讲稿一律用本地 faster-whisper 生成（默认 large-v3-turbo）。
- **PPT 页有时间轴**：`pptnote/v1/schedule/search-ppt` 的每项带 `created_sec`（该页出现在视频中的秒数），
  可与讲稿时间戳对齐，做「按页讲解」。
- **whisper 的 initial_prompt 越短越安全**（2026-10-09 实测，同一 3 分钟样本 A/B/C/D）：
  - 塞 300 字课件术语 → **污染输出**：模型把提示词本身接进正文
    （首段变成「其实是代表强性波动力学2026-06-29第1-2节目」），并反复回吐提示里的词；
  - 只留课程名（几字）→ 干净、无回显。
  原因是 `initial_prompt` 走 `sot_prev` 上下文，等价于「上文」，越长越容易被续写；
  faster-whisper 的 `hotwords` 参数走同一条路径，同样有回显风险。
  所以 `replay.mjs` 只传课程名（≤24 字），**术语纠错放到后面的整理/审计环节**
  （那里有课件原文可对照，不需要模型去猜）。
- **听错的术语要拦在整理阶段**：实测讲稿把「公式」听成「公司」（「新一页公司」）、
  还出现过无出处的「十二定律」。整理稿/成稿提示词里加了护栏：先与课件术语对照，
  对不上就换成稳妥表述或省略，不许原样照抄讲不通的词。
- **页码时间轴的落地**（`server/pages.mjs`）：学校给的图片直链文件名就是毫秒时间戳
  （`.../34160.jpg` = 34.16s），但下载会重命名成 `0001.jpg`，时间就丢了。所以：
  下载时按列表顺序把时间写进 `<课次>.pages.json`；老课件用
  `pageTimesByTitle()` 按「课程名 / 课次名」反查 course_id / sub_id（课程列表缓存 10 分钟），
  重新取一次列表补齐，再存成同一格式。
- **按页切片**：第 i 页的讲解 = 时间落在 `[本页出现时刻, 下一页出现时刻)` 的转写段落
  （`narrationByPage()`）。实测一节 18 页复习课，13 页有讲解；没讲到的页（翻得快或静默）留空。
- **清洗会打乱「页号 ↔ 文件号」**，切片必须按下面两条来（否则整节课对不上）：
  - 键用**原文页号**（`<!-- page N: 0050.jpg -->` 的 N），不是文件名里的编号——
    清洗删帧后 md 第 1 页可能就是 `0050.jpg`；
  - 只用**清洗后仍在的页**划时间片：某页讲解 = 从该页出现到**下一张保留页**出现。
    若让被删帧参与切片，它们占用的讲解会挂到已不存在的页号上丢失
    （实测测井那节 95 帧删 55 帧，丢了 88 秒）。
  另外，只有图、OCR 无文字的页照样要进流水线（「一张图讲一节课」就是这种情况），有讲稿就靠讲稿写。
- **关键图怎么贴进笔记**：图片素材有两个来源——
  ① 转 MD 时裁出的图形素材 `<课次>_assets/pNNNN/figures/*.jpg`（已在笔记目录，天然可引用）；
  ② 图文页（OCR 文字 < 60 字）的整页原图，**复制**到 `<课次>_assets/slides/<name>` 再引用
  ——课件图在数据目录、笔记在笔记目录，两边可以分开（笔记可写进 Obsidian 库），
  相对路径跨不过去，而复习页 (`resolveMdAssets`) 与打印页 (`print.html`) 都只按笔记目录解析图片。
  整理稿阶段每页列出「可贴的图」，成稿挑关键的那张贴；写完后统一校验，
  **指向不存在文件的图片引用会被丢掉**（模型可能编路径），不留破图。
  但布局模型（DocLayout-YOLO）会把**校徽、装饰、手写痕迹**也裁成 figure——实测踩过
  「第 11 页图 = 107×37 的涂鸦」「第 14 页图 = 130×133 的校徽」。所以候选要按尺寸过滤：
  **最小边 ≥150px 且面积 ≥整页 3%**；这一节课的实测分布是垃圾件 0.4% / 1.9%，
  真图 6.8% / 9.2% / 11.1% / 17.0%，切得干净。若某页的裁片全被判成装饰（或整页就是一张图），
  回退成**整页原图**（复制到 `<课次>_assets/slides/`），宁可贴整页也不贴垃圾。
- **看图讲解（图注）**：整理稿生成前，把**整页截图**交给视觉模型写 2-4 句图注
  （画的是什么 / 坐标轴 / 几何关系 / 与知识点关系），作为【图示】进入整理稿输入。
  档位自动挑：`visionCloud`（配了 key 才试）→ `visionLocal`（Ollama）→ `text`
  ——最后这个是因为**文本档也可能是多模态的**：实测 `deepseek-flash` 能逐行读对
  幻灯片上的考试安排表（日期/时间/地点/班级全对），一张 1080p 幻灯片约 600 prompt tokens。
  探测结果按 `baseUrl|model` 缓存在进程内，不可用的档位下次直接跳过；一个都不可用就跳过图注。
  上限 30 页/课次，按「OCR 文字少的页优先」排序——真正的图文页先拿到图注。
  实测一节课 8 页图注、耗时约 3 秒（并发 3），笔记里出现「AB、AC 为竖直/水平面，CD 为斜面」
  「只涉及 $x_1$、$x_2$ 两个方向」这类只有看图才能确定的信息。
  笔记生成的「整理稿」阶段把讲解附在对应页后面（`【老师讲解·语音转写】`），并在提示词里说明
  「可能有同音错字，理解语义后再整理，不要照抄；与课件冲突时以课件为准」。
  整理稿缓存（`.note.work.md`）除了比对原文 md 的 mtime，也会比 `trans.json`——后补讲稿不会被旧缓存挡住。
- **审计也要吃讲稿**（否则会自相矛盾）：`runAudit` 的忠实度核对原本只比对课件原文，
  讲稿带进笔记的内容会被判 `unsupported` 并被自动「修正」掉。现在核对材料是
  「课件原文 + 该页老师讲解」，提示词明确「两者之一支持即为支持；讲解里的同音错字不算不符」，
  并要求「依据只来自讲解、且不是明显错字的条目不要改动」。
- **多页条目按全部引用页取材料**：条目常同时引用 `#page=7` 和 `#page=8`，
  只取首引页会把别页的内容误判成没依据（实测「矩阵式 $\bar\tau=\beta\tau\beta^T$」因此被削掉）。
  现在按该组条目引用到的页（最多 4 页）拼接原文与讲解。
- **知识点清单的缓存版本**：`<课次>.points.json` 带 `v` 字段（当前 2 = 纳入讲稿）。
  版本不符即重提；复用旧清单时**原样写回旧版本号**，避免旧内容被贴上「新版」标签继续复用
  （踩过：复用一次就把 v1 洗成 v2，之后永远不再重提）。
  实测纳入讲稿后同一节课的知识点从 26 条涨到 57 条，多出的是考试题型、考试时间地点等口头信息。
- **会话不持久**：问渠的 cookie 是会话级（关浏览器即失效），「记住登录 + 自动重登」是必要能力。
