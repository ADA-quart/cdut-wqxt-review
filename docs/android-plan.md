# 清渠 · 移动端规划与数据同步设计

> 2026-10-07 · 配套排版原型见 [`android-plan.html`](android-plan.html)

## 一句话定位

**电脑端 = 内容生产端**（下载、OCR 转 MD、清洗、生成笔记）；
**手机端 = 学习端**（读笔记、看课件、问答、标记、复习）。
同步 = **内容单向下发 + 学习状态双向回流**。

### 目标设备（开发优先级，2026-10-07 调整）

| 优先级 | 设备 | 屏幕 | 布局目标 |
|---|---|---|---|
| **主（重点）** | 小米平板 6 Pro（Android 15 / 澎湃 OS，12GB） | 11″ 2880×1800 @320dpi = **1440×900dp 横屏** | 完整三栏：左笔记 + 右上课件 + 右下对话；触摸/双指缩放优化 |
| 次 | 手机 | ~390×850dp 竖屏 | 三 Tab 布局（原方案，保留） |

平板是日常复习主力：字大、图清、笔记和课件同屏对照。所有布局决策以平板横屏为第一优先。

## 一、手机端做什么 / 不做什么

**保留（学习全流程）**
- 笔记阅读：公式渲染、页码角标、知识链、阅读进度
- 课件看图：缩放、翻页、角标跳页、⭐ 重点 / ❓ 错题 / ✓ 掌握
- 引用提问：划词 → 引用 → LLM 对话（直连自有 API），含历史
- 复习队列（间隔重复）、课次切换、全库搜索

**不做（重活留在电脑）**
- 下载课件、OCR 转 MD、清洗去重、生成笔记、PDF 导出
- 云同步、账号系统（保持本地优先）

## 二、界面（详见原型）

- **平板横屏（主场景，1440×900dp）：完整三栏**——左笔记、右上课件、右下对话，与桌面端同构
- **平板竖屏（900×1440dp）：双栏**——左笔记、右侧上课件下对话（可折叠回三 Tab）
- 手机竖屏：笔记 / 课件 / 问答 三个整页，底部 Tab，角标与引用串联
- 同一套前端 + CSS 断点，不写第二套 UI

## 三、数据同步设计

### 3.1 两类数据

| 数据 | 方向 | 合并原则 |
|---|---|---|
| **内容**：笔记、课件图、知识链、课程索引 | 电脑 → 手机（单向，电脑为准） | 按课次版本比对，新增 / 更新 / 跳过 |
| **学习状态**：阅读进度、⭐❓✓ 标记、对话历史、复习卡 | 双向 | 时间新者赢 + 并集去重 |

### 3.2 三种包（同一 zip 格式，manifest.type 区分）

| 类型 | 内容 | 用途 |
|---|---|---|
| `content` 内容包 | 笔记 + 图片 + 角标索引（全部 / 按课程 / 单课） | 电脑 → 手机，首次全量、日常增量 |
| `state` 学习记录包 | 进度 + 标记 + 对话 + 复习卡（很小，几 MB） | 双向：手机 ←→ 电脑回流合并 |
| `full` 全量备份包 | 内容 + 状态 | 备份、换机 |

包结构与现有 format 1 兼容，仅新增 `progress/` 目录与字段：

```
manifest.json     # app / format:2 / type / exportedAt / device
                  # lessons[]: { course, lesson, contentVersion, stateUpdatedAt }
notes/  images/  cards/  chats/  progress/
```

- `contentVersion`：课次内容指纹（笔记 mtime + 页数 + 大小），用于增量判定
- 旧包（format 1）继续可导入，按无 type 处理为 content

### 3.3 合并规则（双端同一套实现）

- **内容**：手机对比 `installed.json` 快照 → 新增课次直接装、版本不同原子替换、相同跳过
- **进度**：`updatedAt` 较新者胜（"电脑看到哪，手机接着看"）
- **标记 / 复习卡**：按卡 id 合并，取较新的操作时间
- **对话**：按消息 id 并集去重，两边都不丢
- 不需要弹窗让用户解决冲突——以上规则足够安全

### 3.4 现状缺口（P0 必须先补）

1. **阅读进度目前只存在浏览器 localStorage** → 改为随课次存服务端（`<课次>.progress.json`），首次打开复习页时把旧值迁移上报
2. 导出目前只有全量 → 增加 **按课程**、**单课**、**仅学习记录** 三种范围
3. 导入目前只写文件（跳过/覆盖）→ 增加 **合并逻辑**（3.3 的规则）

### 3.5 搬运方式

- **v1（先做）**：手动搬包——微信 / QQ / 网盘 / 数据线传 zip，手机导入
- **v2（后做）**：同一 WiFi 局域网直连——电脑显示二维码 / 6 位配对码，手机扫码后一键「拉内容 / 推记录」，按 contentVersion 只传差异

## 四、开发阶段

| 阶段 | 内容 | 产出 |
|---|---|---|
| **P0 桌面端地基** | 进度入库 + 迁移、范围导出、包格式 v2、合并导入 | 电脑能产出手机要吃的所有包 |
| **P1 安卓骨架** | Capacitor 工程、响应式复习页、导入包 → 课程列表 → 只读浏览 | 能装在手机上看的 APK |
| **P2 学习交互** | LLM 直连（Keystore 存 Key）、引用提问、⭐❓✓、复习队列、进度记录、搜索 | 完整的手机学习端 |
| **P3 回流闭环** | 手机导出学习记录包 → 电脑合并；电脑新包 → 手机增量更新 | 双向同步闭环 |
| **P4 体验** | 局域网一键同步、二维码配对、更新检查 | 日常无感使用 |

## 五、技术选型

- 骨架调研（2026-10）：**结论 Capacitor 8**，对比与理由详见 [mobile-stack-survey.md](mobile-stack-survey.md)
- **Capacitor 套壳**（与 ITDC 同一打法），CI 自动出 APK
- 复用现有零依赖前端（`public/`），加响应式断点与手机 Tab 布局
- 数据层适配器：桌面走 `/api`（Node 服务），手机走本地包（Capacitor Filesystem 解压到私有目录）
- LLM：直连用户的 OpenAI 兼容端点，Key 存 Android Keystore
- 存储：全部在 App 私有目录，相册 / 下载 / 文件管理器不可见，卸载即清

## 六、边界

- 手机不产生内容，只产生学习状态——回流包永远很小
- 视频 / 录播不参与同步
- 无服务器依赖：所有同步都是端到端（手动包或局域网）
